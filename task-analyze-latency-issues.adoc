= Analiza los problemas de latencia en Workload Factory para EDA
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Consulta los retrasos detectados y utiliza herramientas automatizadas para identificar la causa y solucionar el bajo rendimiento en tus volúmenes FSx para ONTAP.



== Antes de empezar

Debes tener link:task-configure-latency-monitoring.html["monitorización de latencia configurada"] antes de poder ver y analizar eventos de latencia.



== Ver eventos de latencia

La tabla de eventos de latencia muestra en un solo lugar todos los eventos de advertencia y críticos de las últimas 72 horas.

.Acerca de esta tarea
* Solo se muestra la infracción más reciente de cada volumen. Las infracciones anteriores del mismo volumen no se muestran.
* Los eventos se eliminan automáticamente después de 72 horas.
* Se muestra un máximo de 200 eventos. Los eventos antiguos se eliminan a medida que se añaden nuevos eventos.
* Los eventos aparecen incluso sin un enlace al sistema de archivos. Se requiere un enlace para ver los detalles básicos del análisis o ejecutar un análisis de IA.


.Pasos
. Inicie sesión utilizando uno de los link:https://docs.netapp.com/us-en/workload-setup-admin/console-experiences.html["experiencias de consola"^].
. Selecciona el menú image:workloads-menu-icon.png["El icono del menú hamburguesa"] y luego selecciona *EDA*.
. Selecciona la pestaña *Latencia*.
. Revisa la información de cada evento en la tabla de eventos de latencia.
. Para ver los detalles de un evento de latencia, selecciona el evento en la columna *Severity*. Esto abre un panel de análisis de latencia para ese evento.
. Para ordenar la tabla, selecciona cualquier encabezado de columna. Por defecto, los eventos críticos se muestran primero ordenados por tiempo, seguidos de los eventos de advertencia ordenados por tiempo.
. Para descartar uno o más eventos, al lado de cada evento selecciona image:icon-action.png["El icono del menú de acciones"] *Dismiss*.
. Para añadir columnas a la tabla, selecciona image:column-icon.png["El icono de la columna"], elige las columnas y selecciona *Aplicar*.
. Para analizar las tendencias de latencia a lo largo del tiempo, selecciona un evento para abrir el panel de análisis de latencia. Usa la pestaña *A lo largo del tiempo* para ver el gráfico interactivo de latencia. Consulta link:task-analyze-latency-trends.html["Analiza las tendencias de latencia"] para más detalles.




== Analizar un evento de latencia

El análisis básico te ayuda a encontrar rápidamente qué está causando las ralentizaciones sin tener que investigar manualmente.



=== Panel de análisis de latencia

Selecciona un evento de latencia en la columna *Severity* para abrir el panel de análisis de latencia de ese evento. El panel incluye pestañas que ofrecen diferentes vistas del evento de latencia:

* *Resumen*: Muestra los resultados básicos que identifican qué componente está causando la demora
* *A lo largo del tiempo*: muestra un gráfico de latencia interactivo con datos históricos




==== Ficha de descripción general

La pestaña *Resumen* muestra los resultados de un análisis automático. Si el archivo está vinculado al sistema de archivos, muestra un desglose de los componentes y te indica cuál está causando el retraso. Si no existe ningún vínculo, se te pedirá que añadas uno.

Si se ha configurado un ARN de modelo de Amazon Bedrock, la pestaña **Descripción general** te permite realizar análisis de IA sobre datos y escenarios de clúster. Si Bedrock no está configurado, la pestaña muestra un enlace a la página de configuración de Storage Workloads de ese sistema de archivos, donde puedes configurar el acceso a Bedrock.



==== Pestaña a lo largo del tiempo

La pestaña **A lo largo del tiempo** muestra gráficos interactivos de las métricas de CloudWatch para el volumen afectado. Estos gráficos muestran la latencia, las IOPS y el rendimiento a lo largo del tiempo. Muestran métricas de lectura o escritura, dependiendo de qué alarma haya activado el evento. Puedes elegir diferentes intervalos de tiempo (1H, 3H, 12H, 24H, 72H) y usar un filtro para ver todas, solo lectura, solo escritura o las operaciones de metadatos.

Para obtener instrucciones detalladas sobre cómo utilizar los gráficos, consulta link:task-analyze-latency-trends.html["Analiza las tendencias de latencia"].



=== Pasos

. En la pestaña *Latencia*, localiza el evento que quieres analizar.
. En la columna *Severidad*, selecciona un evento de latencia para abrir un panel de análisis de ese evento.
. Consulta la pestaña *Descripción general*. Si hay un enlace conectado, abre el desglose de componentes para ver de dónde proviene el retraso. Si no hay ningún enlace conectado, selecciona el mensaje para establecer uno y poder analizar los componentes.
. Opcionalmente, selecciona la pestaña *A lo largo del tiempo* para ver las tendencias de latencia del volumen afectado.
. Si la latencia necesita una investigación más profunda, como posibles problemas de datos o del clúster, ejecuta el análisis de IA.




== Ejecuta un análisis con IA

El análisis mediante IA permite realizar una investigación más exhaustiva para determinar la causa raíz específica y las posibles medidas correctivas.

.Antes de empezar
Configura un ARN de modelo de Amazon Bedrock en los ajustes de Workload Factory, consulta link:https://docs.netapp.com/us-en/workload-genai/knowledge-base/requirements-knowledge-base.html#basic-genai-requirements["Requisitos básicos de GenAI"^].

.Acerca de esta tarea
Cuando ejecutas un análisis de IA, el sistema actualiza automáticamente los datos básicos del análisis y los usa como entrada para el análisis de IA.

.Pasos
. En la pestaña *Latencia*, localiza el evento que quieres analizar.
. En la columna *Severidad*, selecciona un evento de latencia para abrir un panel de análisis de ese evento.
+
Si no hay ningún enlace asociado con el sistema de archivos, se muestra un aviso pidiéndote que asocies un enlace con el sistema de archivos afectado. Selecciona el aviso para que te redirijan a la página de configuración de enlaces para ese sistema de archivos.

. Revisa la pestaña *Overview* para entender los resultados básicos del análisis e identificar la fuente de latencia.
. Si la fuente de la latencia se identifica como datos o clúster, selecciona *Analizar* para ejecutar el análisis de IA.
. Revisa los resultados, incluyendo:
+
** Explicación de la posible causa raíz
** Lista de clientes EC2 afectados
** Medidas correctoras recomendadas


. Sigue los pasos recomendados para solucionar el problema de latencia.
. Después de hacer los cambios, revisa la tabla de eventos de latencia para confirmar que el problema está solucionado.




== Mejores prácticas

Ten en cuenta estas recomendaciones al analizar los problemas de latencia:

* *Supervisar tendencias*: Revisa periódicamente la tabla de eventos de latencia para detectar patrones o problemas recurrentes que puedan indicar fallos de configuración.
* *Utiliza el análisis de IA de forma estratégica*: Utiliza el análisis de IA al revisar los datos si el análisis básico lo sugiere. El análisis de IA puede revelar información más profunda sobre problemas de rendimiento complejos que necesitan una solución de problemas detallada.
* *Revisa los eventos descartados*: Revisa periódicamente por qué se descartaron los eventos para ver si deberías ajustar los umbrales o mejorar el sistema.


Para conocer las mejores prácticas sobre cómo analizar las tendencias de latencia, consulta link:task-analyze-latency-trends.html#graph-interpretation["Interpretación de gráficos"].
